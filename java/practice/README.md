# 练习工程与章节作业规范

本目录承载 IDEA 练习工程、章节作业和实际运行证据。章节文件的组织规则在本文维护，正式学习状态见 [PROGRESS](../PROGRESS.md)。

## IDEA Java 项目

在 IDEA 中打开外层目录 `/Users/yu/Desktop/yumengyuan/learn_everything/java/practice`，选择“新窗口”。内层 `practice/` 已标记为 Java 源码根目录；进入对应章节目录后，右键 → 新建 → Java 类，编写 `.java` 文件即可使用类型检查、代码补全、参数提示和运行入口。

项目 SDK 使用本机已注册的 JDK `21`（Homebrew OpenJDK 21.0.11）；语言级别和字节码目标均为 Java 8。当前为纯 Java 练习项目，尚未引入 Spring、MyBatis、JUnit 或数据库依赖。

文字作业写在章节 `README.md` 中；需要完整 Java 类型检查和运行时，将代码写入该章节目录的 `.java` 文件。普通 Java 类的 `package` 与源码根之下的目录对应，例如 `practice/m00_2/ValidationDemo.java` 声明 `package m00_2;`。

以 `practice/m00_2/ValidationDemo.java` 为命令格式示例，在本项目根目录通过终端编译运行：

```sh
mkdir -p out/production/practice
/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home/bin/javac --release 8 -encoding UTF-8 -d out/production/practice practice/m00_2/ValidationDemo.java
/opt/homebrew/opt/openjdk@21/libexec/openjdk.jdk/Contents/Home/bin/java -cp out/production/practice m00_2.ValidationDemo
```

上述路径和类名仅演示命令格式；本次未创建该章节或代码文件，实际命令按当前题目确定。IDEA 的编译输出位于 `out/`；`.idea/` 和 `out/` 已排除在源码目录之外。

## 章节作业规范

### 目录与命名

- 作业根目录固定为 `/Users/yu/Desktop/yumengyuan/learn_everything/java/practice/practice/`。
- 这里的“章节”对应 ROADMAP 的一个学习单元，例如 `M00.1`；`M00` 仍称模块。
- 每章一个目录：`M00.1 → m00_1/`、`M01.2 → m01_2/`。使用小写字母、数字和下划线，兼容当前 Java 源码根的包名规则。章节主题写在文档标题中。
- 默认每章一份 `README.md`，聚合文字练习及其解答。首次布置该章作业时创建目录，后续向已有文件追加题目。
- 当前示例：[M00.1 章节作业](practice/m00_1/README.md)。

```text
practice/                         # IDEA 工程目录
├── README.md                     # 本规范
└── practice/                     # 作业根目录、普通 Java 源码根
    └── m00_1/                    # 一个章节
        └── README.md             # 章内 Q01、Q02……题目与解答
```

### 什么时候拆文件

| 内容 | 默认组织方式 |
| --- | --- |
| 简答、源码定位、输出推理、同章补练与复查 | 在该章 `README.md` 中按题号分节，不按每道题新建 Markdown 文件 |
| 需要编译运行的 Java 代码 | 在章节目录中按类创建 `.java` 文件；文件名与公开类名一致，包名与目录对应；题目仍写在章内 README 并链接代码 |
| 需要独立依赖、构建配置和测试结构的完整工程 | 按实际任务在章节目录内创建 `project/`，遵循构建工具目录约定；导入时核对 IDEA 源码根，避免与外层源码根重叠 |
| 实际运行日志、截图等证据 | 产生材料时再创建章节内的 `evidence/`，在对应题目中链接 |

拆分以代码运行、独立工程或附件的实际需要为依据。普通文字题用同一文件，便于连续填写、回看和核验；需要运行的代码保留正常的 Java 文件结构。

### 作业设计与交付

每题先确定要训练的核心能力，再选择能证明它的最小任务。每个提交项都应回答“这能证明哪项能力”；导师能从源码、配置、文件或运行结果中直接观察的信息，由导师核验。编写实现、选择测试边界、解释原因是学习任务；整理验收材料由导师承担。

| 作业类型 | 学生需要交付 | 导师负责 |
| --- | --- | --- |
| 编程与测试 | 保存实现和测试代码，告知“已完成”或“已保存” | 读取代码、检查关键边界、执行必要验证、解释结果 |
| 概念理解 | 仅回答代码无法证明的关键理解或迁移问题，每次一道，可直接在对话作答 | 针对尚未确认的能力出题、反馈并归档原话 |
| 操作与排障 | 当操作本身是学习目标时亲手练习；必要时说明定位原因或修复判断 | 读取可访问的环境和运行结果，复现问题，核验产物与修复效果 |
| 遇到卡点 | 说明正在做什么、卡在哪里；没有卡点就无需填写 | 先检查已有上下文、源码和环境，再补讲或给最小提示 |

- **默认提交方式**：保存作业文件并告知完成即可。源码路径、方法列表、环境版本、执行时间、目录、命令、测试数量和报告位置等由导师自行读取或采集；不要求复制源码、粘贴日志、重复填写结果或用截图证明可直接核验的事实。
- **保留有效练习**：运行、调试、分析失败等步骤应服务于明确能力。已完成的操作无需为了补材料重做；需要理解失败时，可使用真实失败或导师在临时副本中构造的演示。若目标是独立操作或修复，仍由学生完成该动作，导师复跑不等于学生会操作。
- **文字按需出现**：有关键理解题才设置解答区；纯代码题直接链接代码。卡点、思路和额外辅助可按需说明，不设置每题必填的复盘、辅助声明或过程流水表。接口文档、设计说明等若本身就是训练目标，则按题目明确要求交付。
- **不可观察时才补充信息**：导师先尝试读取或复现；确因环境不可访问、失败无法复现等缺少判断依据时，说明缺什么及用途，只请求最小必要内容，例如关键错误片段。无需提交整份日志、完整操作过程或截图集。
- **核验与掌握分开**：导师自动整理实际提供的提示、已观察的代码和核验结论，区分用户作答与导师运行。源码正确或导师测试通过不自动证明用户独立掌握；需要确认理解时，只补一道针对关键缺口的问题，不重复考查已经充分验证的内容。
- **反馈抓重点**：先给结论，再指出影响正确性或理解的具体问题，最后给必要的下一步。通过的部分及时结束；历史空白行政栏位与未粘贴的日志无需追补，已有答案和历史记录保留。

### 文档格式与学习流程

源码关系、模块依赖和配置对照由导师自动提取、绘制并给出结论，直接在终端讲解；学习文件保留生成的材料和源码依据。学生的练习以代码实践、小范围定位及关键概念解释为主，不布置手工画图、逐边抄录或批量配置填表。抽问一次一道，可直接在对话回答。

1. 章内 README 顶部写目标、限定阅读范围、最小交付和题目索引。阅读给出直接链接、起止标题及本次范围。
2. 题号按章内首次布置顺序使用 `Q01`、`Q02`……，每题有固定锚点，例如 `<a id="q01"></a>`。追加、补练与复查继续编号；已有题号保持稳定。
3. 每题写清“作业要求”和“验收反馈”，明确必做任务、可用资料、交付方式与验收标准。代码题链接实际文件；需要文字作答时才增加“我的解答”，新题答案留空。
4. 闭卷或迁移题一次布置一道，收到并反馈当前答案后再追加下一题。已完成的题目和答案继续保留在章内。
5. 用户保存代码或必要的文字答案后，导师读取并执行适当验证；口头答案由导师归档到对应题号。原答案与“验收反馈”分开保存，在终端说明结论；导师生成的图、表和讲解不计为用户独立证据。
6. `PROGRESS.md` 是正式状态与当前断点的唯一来源；`learning-records/` 保存有依据的掌握或误解记录。两者链接到章内对应题号，未回答题保持未评分。

### 迁移与校验

迁移已有作业时，先备份，按稳定题号整理题面、用户解答和已有反馈，再更新所有项目内引用。确认题面代码、用户答案、待答状态与验收结论保留，链接及锚点有效后，移除旧文件副本。

涉及 Java 文件迁移时，同时核对 `package`、`import`、源码根目录和编译运行命令。文件整理本身不产生学习证据或提高验收进度。

## 贯穿工程

在本目录逐步建立一个练习工程：纯 Java 业务方法 → Spring 内存 API → MySQL/MyBatis → 权限与事务 → React 联调 → 本地打包与回滚演练。每一步对应 [ROADMAP](../ROADMAP.md)，保持同一业务上下文。

建议最小业务：一个实体有多个字段分组；支持创建、详情、列表、修改、名称校验、分页、租户隔离、唯一性与并发版本检查。教学模型只保留当前能力所需字段；公司 UDC 的真实语义见 [PROJECT_MAP](../PROJECT_MAP.md)。

首次创建工程时，在其 README 写明实际 JDK、编译目标、Spring Boot/MyBatis/JUnit 和数据库版本、启动及测试命令。语言核心先使用 Java 8 兼容写法；框架版本按公司父 POM 核验后确定，或明确记录独立练习与公司版本的差异。

贯穿工程沿用上述交付分工。导师通过当前代码和必要的实际运行核验结果，记录方式见 [PROGRESS](../PROGRESS.md#保存与续学)；现有测试报告用于定位，本次通过结论以本次执行为依据。

公司构建依赖不可用时，仍可完成纯 Java、SQL 和独立 API 练习；公司环境验收项保持待验证。迁移回公司工程时，先形成改动清单并遵循目标仓库规范。
